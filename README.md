# iOS 개발자 사전 과제

## 과제 목적

주어진 기능을 구현하는 과정에서 요구사항을 해석하고 적절한 구조를 설계하는 능력을 확인하기 위한 과제입니다.

UI 완성도보다는 기능 구현과 설계 과정에 집중해 주세요.

---

## 과제 내용

아래 기능을 제공하는 iOS 앱을 구현해 주세요.

### 1. 상품 목록

DummyJSON Products API를 이용하여 상품 목록을 노출합니다.

**API**

```http
GET https://dummyjson.com/products
```

상품 목록에는 최소한 아래 정보가 표시되어야 합니다.

- 상품명
- 가격
- 상품 이미지
- 찜 여부

상품을 선택하면 상품 상세 화면으로 이동합니다.

### 2. 찜

상품을 찜하거나 찜을 해제할 수 있어야 합니다.

- 찜 상태는 서버 API를 사용하지 않고 로컬에서 관리합니다.
- 앱을 종료하고 다시 실행해도 찜 상태가 유지되어야 합니다.
- 상품 목록과 상품 상세 화면에서 찜 상태가 일관되게 유지되어야 합니다.
- 로컬 저장 방식은 자유롭게 선택할 수 있습니다.

### 3. 상품 상세

상품 상세 화면 진입 시 상품 ID를 이용하여 상세 API를 호출합니다.

**API**

```http
GET https://dummyjson.com/products/{id}
```

예시:

```http
GET https://dummyjson.com/products/1
```

상세 화면에는 상품의 주요 정보를 표시하고 찜 상태를 확인하거나 변경할 수 있어야 합니다.

목록과 상세 화면의 찜 상태는 서로 동기화되어야 합니다.

## 기술 요구사항

- Swift
- SwiftUI
- 비동기 네트워크 처리
- 적절한 상태 관리 구조 적용
- 원격 데이터와 로컬 데이터의 책임을 구분하여 설계
- 프로젝트 및 기본 설정은 지원자가 직접 구성
- 외부 라이브러리 및 의존성 관리 방식은 자유롭게 선택 가능
- Repository를 Clone한 뒤 별도의 추가 작업 없이 빌드 및 실행 가능하도록 구성

특정 아키텍처 패턴의 사용을 요구하지 않습니다. MVVM, MVI, Clean Architecture 등 특정 구조를 반드시 적용하기보다는 과제 규모에 적합한 구조를 직접 판단하여 구성해 주세요.

iOS Deployment Target, 프로젝트 구조, 의존성 관리 방식 등 기본적인 프로젝트 구성 역시 과제의 규모와 요구사항을 고려하여 적절하게 판단해 주세요.

외부 라이브러리를 사용한 경우에는 선택한 이유를 PR에 설명해 주세요.

## 프로젝트 구성

- 별도의 초기 프로젝트나 Git 저장소는 제공하지 않습니다.
- 지원자가 직접 새로운 iOS 프로젝트와 Git Repository를 생성하여 진행합니다.

- 과제 완료 후 지원자가 생성한 Git Repository를 공유해 주세요.

- 과제 수행 시간은 1일입니다.
- 과도한 기능 추가나 UI 완성도보다는 제한된 시간 안에서 요구사항을 해석하고 구현하는 데 집중해 주세요.
